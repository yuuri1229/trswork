# 作業時間トラッカー

時給制のリモートワーク向けに、作業時間をストップウォッチ感覚で記録する Web アプリです。

- ワンタップで作業開始・終了を記録（終了時に作業内容を入力）
- 作業中は「一時停止」「再開」が可能。一時停止していた時間は作業時間に含まれません
- カレンダー表示で日ごとの作業時間・複数件の作業を確認
- 月別の作業時間を棒グラフで表示
- あらかじめ用意した ID（メールアドレス）とパスワードでログインする方式です。アプリからの新規登録はできません。同じアカウントでログインすれば、どの端末からでも自分の記録を確認できます（Firebase Authentication / Firestore を使用）
- 作業時間・経費・レース作業の記録はすべてクラウド（Firestore）に保存されます。外部のスプレッドシートは不要です
- 累計（全期間）の作業時間は「グラフ」タブ、累計の経費・レース作業金額は「経費」タブで確認できます。累計は保存済みの記録から常に自動で集計されます
- ダークモード対応。端末のライト / ダークモード設定に自動で追従します（手動での切り替えはありません）。ダークモードは黒基調の配色です
- 「経費」タブで月ごとに管理
  - 経費: 科目(一般的な勘定科目から選択)・詳細・料金を記録
  - レース作業: 大会名・日数を記録すると、1日あたり16,000円で自動計算

## 開発

```bash
npm install
npm run dev
```

`npm run build` で `dist/` に静的ファイルを出力します。

## ログイン機能について（Firebase）

このアプリはログイン機能に [Firebase](https://firebase.google.com/) の Authentication（メール/パスワード認証）と Firestore（データベース）を使っています。GitHub Pages は静的ファイルしかホストできないため、サーバー機能は Firebase 側にお願いする構成です。

Firebase プロジェクト(`sagyoutime`)の接続情報は [`src/lib/firebase.ts`](./src/lib/firebase.ts) に直接記述しています。この値(`apiKey` など)は本来ブラウザに公開されて問題ない情報で、実際のアクセス制御は Firestore の [`firestore.rules`](./firestore.rules)（ログイン本人しか自分のデータを読み書きできない）が担っています。そのため GitHub Secrets などの追加設定なしでそのまま動作します。

`firestore.rules` を更新した際は、Firebase コンソールの Firestore Database →「ルール」タブで内容を貼り替えて「公開」する必要があります（自動では反映されません）。

別の Firebase プロジェクトに差し替えたい場合は、`.env.example` を `.env.local` にコピーして `VITE_FIREBASE_*` を設定すれば、そちらが優先されます(ローカル開発用)。

### アカウントの作り方（管理者向け）

アプリには新規登録の画面がありません。利用者のアカウントは、あらかじめ Firebase コンソールで作成します。

1. [Firebase コンソール](https://console.firebase.google.com/) でプロジェクト(`sagyoutime`)を開く。
2. 「Authentication」→「ユーザー」→「ユーザーを追加」で、メールアドレス（ID として使います）とパスワードを入力して作成する。
3. 作成したメールアドレスとパスワードを利用者に伝える。利用者はアプリのログイン画面でそれを入力します。

- ログインすれば、どの端末からでも自分の記録・設定を確認できます。
- データはユーザーごとに分離され、他人の記録は見えません。
- パスワードを変更・リセットしたいときや、アカウントを削除したいときも、同じ「ユーザー」画面から操作します。

#### 外部からの勝手な登録を防ぐ設定（推奨）

アプリの画面から新規登録のボタンを消しただけでは、Firebase の接続情報（`src/lib/firebase.ts` の `apiKey` など。公開されても問題ない値です）を使って、誰でも API を直接呼んでアカウントを作れてしまいます。ログインできる人を管理者が用意した人だけに限るには、Firebase コンソールの「Authentication」→「設定」→「ユーザーの操作」で、ユーザーによる「作成（登録）」を無効にしてください。

## GitHub Pages へのホスティング

`main` ブランチに push すると `.github/workflows/deploy.yml` が Vite でビルドし、GitHub Pages に自動デプロイします。

初回のみ、リポジトリの Settings → Pages で「Source: GitHub Actions」を選択してください。

公開 URL は `https://<GitHubユーザー名>.github.io/trswork/` になります（`vite.config.ts` の `base` を変更した場合は URL も変わります）。

## クラウドに保存されるデータ

ログインしたユーザーごとに、Firestore の `users/{uid}` 配下へ次のデータが保存されます。ブラウザのデータを消しても、ログインし直せば復元されます。

| コレクション | 内容 |
| --- | --- |
| `entries` | 作業時間の記録（日付・開始/終了時刻・作業分数・作業内容） |
| `expenses` | 経費の記録（日付・科目・詳細・料金） |
| `raceWork` | レース作業の記録（日付・大会名・日数・金額） |
| `settings` | 設定（氏名） |

累計値は別途保存せず、上記の記録から画面表示のたびに集計します。記録を編集・削除すれば累計にもそのまま反映されます。作業中のタイマー（開始時刻・一時停止の状態）のみ、端末内に保存されます。

### スプレッドシート連携の廃止について

以前あった Google Apps Script 経由のスプレッドシート連携は廃止しました。過去に連携していたスプレッドシート自体は削除されず、そのまま残ります。以前の設定で保存されていた連携先 URL・共有シークレットは、「設定」タブで一度「保存」すると Firestore から消えます。
